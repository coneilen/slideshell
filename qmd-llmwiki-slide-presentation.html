12-minute technical explainer

Engineering knowledge retrieval

QMD and llm.wiki explained simply

How Markdown docs become a useful knowledge system for developers and AI agents.

Timing: 45 seconds. Frame this as a practical talk: not "how to make AI smarter," but how to give AI and engineers the right source material.

The problem

Engineering docs are everywhere, but answers are hard to find.

Your wiki
  • Markdown files
  • RFCs and architecture notes
  • Setup guides and runbooks
  • API docs and team conventions
The user asks

"How does auth work?"

The system needs the correct docs, the correct sections, and the surrounding context.

Timing: 60 seconds. Use a concrete example from the audience's day-to-day work: auth, sync, build release, or incident response.

Why normal search struggles

To a computer, Markdown often looks like disconnected text blobs.

/docs/auth.md /docs/sync.md /docs/building-ios.md
  • Search retrieves noisy chunks
  • Headings and hierarchy get lost
  • Related pages are not connected
  • Answers become fuzzy or incomplete
Timing: 60 seconds. Emphasize that Markdown is human-readable, but systems need help preserving the meaning already encoded in headings, links, and file structure.

What QMD does

QMD is a smart indexer for Markdown.

Documents

It knows a file is a document, not just raw text.

Sections

It tracks headings and section boundaries.

Relationships

It keeps links, tags, metadata, and page connections useful.

Timing: 75 seconds. Say: QMD does not answer the question itself. It prepares the docs so another layer can retrieve accurately.

Mental model

Without QMD, the library is a pile of pages.

Without QMD

Pages are dumped into one giant pile. Search can find words, but not always meaning.

With QMD

Books, chapters, cross-references, and topics are organized so the librarian knows where everything belongs.

Timing: 60 seconds. This is the key junior-engineer-friendly analogy. Keep it simple and visual.

What we built

Two agent skills turn that idea into a daily workflow.

wiki-indexer

Answers: "What do our internal docs already know?"

It indexes ADO wikis plus repo Markdown, then lets agents query them semantically.

scout

Answers: "What does the rest of the world know?"

It researches public web and GitHub sources, writes briefs, and makes them searchable too.

Timing: 40 seconds. This is the transition from concept to implementation. The point is that QMD and llm.wiki are not just abstract patterns; they became two practical skills.

Skill 1: wiki-indexer

wiki-indexer is one search layer over scattered internal knowledge.

Sources
  • Four Azure DevOps wikis
  • Markdown in CrossPlatform
  • Markdown in AndroidClient
  • Markdown in OneDrive.iOS
Boundary

It indexes human-readable docs, not source code.

For code, use IDE search or grep; for engineering knowledge, ask wiki-indexer.

Timing: 50 seconds. Mention the old pain: knowing which wiki to search, running separate searches, and manually stitching context together.

How wiki-indexer uses QMD and llm.wiki

It has three layers: local sources, QMD retrieval, llm.wiki curation.

Local clones
Shallow, sparse, Markdown-only
→
QMD index
BM25 + embeddings + rerank
→
llm.wiki layer
Catalog, changelog, topic pages
  • QMD runs locally, with no document content leaving the machine
  • llm.wiki adds durable summaries and flags stale topic pages when sources change
Timing: 60 seconds. Call out the key implementation detail: QMD gives retrieval; llm.wiki gives maintained, human-readable structure over the raw corpus.

Skill 2: scout

Scout builds on wiki-indexer by adding external research.

wiki-indexer

Internal ADO wikis and in-repo Markdown. Great for "what do we know?"

scout

Public web, GitHub repos, and optional local files. Great for "what should we learn?"

Same QMD backend. Same llm.wiki sensibility. Expanded source domain.

Timing: 50 seconds. Present Scout as the younger sibling: it inherits wiki-indexer's cache style, QMD backend, and llm.wiki pattern, then adds research automation.

How Scout uses QMD and llm.wiki

Scout turns fetched sources into reusable, searchable briefs.

01

02

03

04
Sections

Writers build sections in parallel.

05
Brief

Assembler writes a cited Markdown brief.

Timing: 70 seconds. Explain that for small jobs Scout can synthesize in one pass; for larger research it uses map-reduce: mappers, abstractors, planner, section writers, assembler.

The combined payoff

Both skills feed the same searchable knowledge base.

One query can search
  • Internal wiki pages
  • In-repo design docs
  • Scout research briefs
  • Raw sources behind the briefs

Prior research becomes part of future retrieval.

Timing: 50 seconds. This is the architectural payoff: Scout registers its own collections with QMD, so queries can rank internal docs, external research, and prior briefs together.
